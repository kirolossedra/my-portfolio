## Purpose

`docs/data/` documents **data ownership, persistence, schemas, storage responsibilities, lifecycle and derived-state relationships** across the portfolio.

<a id="what-belongs-here"></a>
## What Belongs Here

- D1/Pinecone/storage responsibility maps;
- canonical vs derived data distinctions;
- schema and migration relationships;
- data lifecycle and recovery expectations;
- retention/ownership boundaries.

<a id="what-does-not-belong-here"></a>
## What Does Not Belong Here

- hosting-provider selection;
- deployment chronology;
- test strategy;
- QC evidence or incident postmortems.

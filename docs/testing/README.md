## Purpose

`docs/testing/` defines **how the repository should be tested**: test levels, automation strategy, coverage expectations and quality gates in CI.

<a id="what-belongs-here"></a>
## What Belongs Here

- unit/integration/E2E strategy;
- test ownership and boundaries;
- CI test expectations;
- regression-suite design;
- test-environment guidance.

<a id="testing-vs-qc"></a>
## Testing vs QC

Testing describes the **strategy and mechanism** for verification. QC stores **specific evidence, incidents and acceptance findings** produced by verification work.

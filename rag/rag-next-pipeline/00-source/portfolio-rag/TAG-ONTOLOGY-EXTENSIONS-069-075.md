# Tag Ontology Extensions — Repositories 069–075

This file extends the canonical positive-evidence tag vocabulary for repositories 069 through 075.

The global corpus rule remains unchanged: a tag represents positively evidenced implementation or a clearly qualified repository state. Repository names alone do not establish implementation capabilities.

## Machine Learning Delivery

- `tensorflow-js` — TensorFlow.js is materially used to load, preprocess for, or execute a model in the browser.
- `browser-ml-inference` — Machine-learning inference executes directly in browser JavaScript.
- `client-side-model-loading` — A serialized trained model is loaded by client-side application code.
- `model-artifact-loading` — Application code loads model topology/weights or comparable serialized model artifacts.
- `digit-recognition` — Application materially performs or exposes digit-classification inference.
- `handwritten-digit-recognition` — User-created handwritten digit input is materially routed into a recognition model.
- `image-preprocessing` — Image input is materially transformed for model consumption through operations such as grayscale conversion, resizing, normalization, inversion, or contrast scaling.
- `logistic-regression-inference` — A logistic-regression model is materially executed from stored weights/bias and a sigmoid calculation.
- `browser-logistic-regression` — Logistic-regression inference is implemented directly in browser JavaScript.
- `static-model-deployment` — A model and its inference application are distributed through static web artifacts rather than a required application server.
- `tensor-lifecycle-management` — Browser ML code explicitly disposes or otherwise manages temporary tensor resources.
- `model-deployment-prototype` — Repository is materially structured around exercising how trained model behavior is delivered into a user-operable runtime.
- `machine-learning-demo` — A user-facing interface materially exposes machine-learning model behavior.

## Browser Interaction and Visualization

- `canvas-api` — HTML Canvas is materially used for drawing, image processing, visualization, or input.
- `canvas-drawing-input` — Users can create input by drawing directly on a browser canvas.
- `image-upload` — Browser code materially accepts and processes uploaded image files.
- `async-javascript` — `async`/`await`, promises, or comparable asynchronous JavaScript materially structure application behavior.
- `interactive-forms` — Form controls materially drive application logic rather than serving only as static markup.
- `chart-js` — Chart.js materially renders charts in the application.
- `data-visualization` — Repository contains implemented data visualization behavior.
- `responsive-timeline` — A responsive timeline/card interface is materially implemented.

## Reuse and Attribution

- `prototype-reuse-and-integration` — A previously developed implementation artifact is reused inside a broader product or portfolio surface and the corpus explicitly treats it as integration rather than a separate original implementation.

## Windows Scripting and Automation

- `windows-batch` — Windows Batch files contain material executable automation logic.
- `powershell` — PowerShell scripts contain material executable automation logic.
- `filesystem-automation` — Scripts materially automate filesystem operations such as rename, create, search, move, or delete.
- `file-renaming` — Script materially renames files according to a defined rule.
- `directory-generation` — Script materially creates directories from input data or a naming rule.
- `recursive-directory-search` — Script recursively searches a directory hierarchy for matching directories.
- `recursive-file-deletion` — Script recursively deletes matching filesystem content.
- `text-file-processing` — Script materially processes line-oriented text-file input.
- `parameterized-script` — Script accepts a runtime parameter that changes the path or behavior being operated on.
- `scripting-utility-collection` — Repository contains multiple focused scripting utilities.
- `operational-tooling` — Code implements practical operations/developer-maintenance tasks.

## Habit and Touch Interaction

- `habit-tracker` — Application materially supports creation or tracking of habits/daily activities.
- `mobile-first-ui` — Interface contains material interaction/layout decisions specifically oriented toward phone/touch use.
- `touch-interaction` — Touch events materially control application behavior.
- `touch-long-press` — Application explicitly detects a long-press gesture using touch timing/state.
- `custom-context-menu` — Application implements its own context menu for secondary actions.
- `dynamic-dom` — Application materially creates, updates, or removes DOM nodes at runtime.
- `modal-dialog` — Modal UI is materially implemented as part of the application workflow.
- `emoji-picker` — User selects an emoji through an implemented picker/control.
- `activity-tracking` — Application materially represents user activities and their state.
- `completion-state` — Items can materially transition between incomplete/completed UI state.
- `create-edit-delete-ui` — User interface materially supports creating, editing, and deleting application objects.
- `activity-categorization` — Activities are materially assigned to explicit categories.

## Firebase and Localization

- `firebase` — Firebase SDK/services are materially integrated into application code.
- `firebase-realtime-database` — Firebase Realtime Database is materially used for data persistence.
- `browser-database-write` — Browser application code directly performs a persistent database write.
- `hierarchical-data-model` — Stored data is materially organized through a hierarchical/path-based structure.
- `timestamped-records` — Persisted application records materially include creation/event timestamps.
- `runtime-localization` — User-facing labels/messages/options are switched at runtime according to active language/locale state.
- `bilingual-ui` — Application materially supports two user-interface languages.
- `english-french-ui` — English and French are the implemented user-interface languages.
- `es-modules` — JavaScript ES module imports materially structure browser application dependencies.
- `cloud-backed-frontend` — Browser frontend directly uses a hosted backend/data service.
- `language-learning-utility` — User-facing application materially supports language-learning data/workflows.
- `vocabulary-tracking` — Application materially records or organizes vocabulary-learning entries.

## Repository State / Topic Markers

- `course-topic-marker` — Sparse repository whose positive evidence is limited to a named course/topic marker.
- `project-topic-marker` — Sparse repository whose positive evidence is limited to a named project/topic marker.
